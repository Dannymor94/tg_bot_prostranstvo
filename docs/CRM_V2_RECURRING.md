# CRM v2 — recurring weekly rentals (2026-11-25)

## Implemented
- Tenant directory column F, Регулярное расписание, accepts explicit weekly rules such as Пн 18:30-20:00; Ср 18:30-20:00. Strict Moscow-time intervals within configured opening hours; one interval per weekday per tenant for MVP. Blank means no recurrence. Category and recurrence are independent; ordinary, regular discounted and non-billable internal tenants use the same scheduling path.
- CrmRecurring.gs expands future dates, creates stable tenant/date occurrence IDs, checks actual occupied time through the shared availability port, persists original quote with a new Sheet row and delegates Calendar/accepted writes to the existing reconciliation loop. No parallel Calendar writer. Existing same-tenant exact bookings, moved/cancelled historical occurrences and prior IDs are not recreated. Other bookings for the same tenant on that date and occupied slots require review.
- CrmGasV2.gs includes recurrence in the locked TEST pass after tenant/calendar/sheet intake, with explicit CRM_V2_RECURRING_TEST_ENABLED=true and existing TEST write flag. Rolling horizon: 30 days from tomorrow, max 5 newly staged bookings per pass. Report includes created/existing/review/errors/invalid rules/limited. Invalid rule blocks recurrence generation for the pass. No retroactive bookings.
- Rules apply to new occurrences only. Editing/removing a rule does not move, cancel or reprice existing bookings; administrator changes those explicitly. A conflicting proposed rule is not automatically resolved; the first available candidate in date/time/ID order may be staged, later conflicting candidate is flagged. Existing historical data and all cancellations must be retained through migration. No real schedule seeded yet.
- Automated tests cover parsing, future dates, paid/discounted/internal quote, bounded repeated staging and reconciliation, preservation of cancelled/moved occurrences, prior manual booking history, occupied slots and ambiguous writes. Code/test commit c5e4d4c882ecd2e5f570dad8cf9e5cea52c982dc. CI result tracked in PR.
