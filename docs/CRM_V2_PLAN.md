## Product
One booking per row; edits originate in Telegram, Google Calendar or Sheets and converge to the same record. Sheets is canonical accepted state; external edits are proposed changes, not blindly authoritative. Private calendar with structured editable fields (tenant, direction, format, payment intent); no financial details exposed in public calendar or public bot. New unknown tenant/format => draft requiring clarification, but reserve actual calendar occupied time. Users choose any interface.
Visible sheets: Главная, Аренды, Арендаторы, Оплаты, Настройки. Native filters, validations, protected formulas; no custom Sheets UI required. Hidden/protected operational journal, not a security boundary. Only trusted editors access CRM. Booking columns date/start/end/tenant/direction/format/quoted total/paid/balance/status; immutable booking UUID, calendar REST event ID, revision, tariff version and sync state protected. Sort by ID, never row number. Tenants have unique ID, name/aliases, default direction/format, manual regular flag, optional contacts. Payment entries immutable ID, booking ID, amount in kopecks, received date, operator/source; refunds/reversals are separate signed entries. Paid/balance derived; checkbox or structured Calendar payment intent creates an idempotent ledger entry, not a competing paid boolean. Calendar payment intent on already partial paid booking means outstanding balance only, after validation; reversal/refund requires explicit action; never silently delete receipts. Cancellation preserves receipts; refund/credit decision flagged.
Four admin Telegram sections: Расписание / Добавить аренду / Оплаты / Арендаторы. Owner-only settings/diagnostics. Allowlist by Telegram user ID and private chat, enforce on every mutation and callback. Public read-only free windows/prices, no names or finances. Confirm mutation, recheck availability at commit. No LLM/API billing/VPS/DB/Mini App.
 
## Tariffs
Owner clarification (2026-11-25): distinguish ordinary paid tenants, regular paid tenants (10% discount), and internal studio bookings (non-billable, zero quote, no receivable or revenue, still occupy time and count toward utilization). Internal is an explicit category, not a 100% promotional discount and not a payment receipt. Keep internal/paid classification separate from recurrence; a recurring internal booking is still free. Snapshot billing category at confirmation and preserve historical receipts; changing the tenant category must not silently rewrite previous prices or finances. Zero-value internal bookings should display as non-billable rather than overdue or paid by a fabricated receipt. The owner has confirmed the initial four classifications privately; do not publish tenant names or source records in the public repository. Import them into the private CRM only after the schema and billing paths support this category. History-based suggestions require administrator confirmation; no automatic discounts based on repeated bookings alone.

Sat–Sun individual 500/700/1000; group 900/900/1000. Periods [06:00,10:00), [10:00,17:00), [17:00,23:00). Split across boundaries; prorate by minute, round final discounted total once to kopecks. Weekday determined in Europe/Moscow from civil date; weekends Sat/Sun (no holiday override). Manual regular-tenant flag => 10% discount per owner's clarification; poster says >10 hours/month, so confirm public policy before production. Price snapshot at confirmation; future tariff edits do not affect existing bookings. Move previews revised quote, preserves payments; external direct moves with changed price update prospective amount only under agreed policy, otherwise mark price review. Never silently reprice completed bookings.
Read-only requests: bare weekday, nearest weekday, today/tomorrow, morning/day/evening, exact range, duration. Today inclusive if requested period still has future time; nearest weekday moves to next occurrence if period wholly elapsed; no silent shift if fully booked. ## Consistency and recovery
One Apps Script project per environment, one core for all write paths. Common script lock for app writes; manual UI edits bypass lock, so compare last accepted snapshots/current values and Calendar ETag preconditions, re-read before/after. Three-way merge disjoint fields, same-field divergent changes => conflict and targeted freeze, never last-write-wins for money. Pending operation journal persists stable operation ID, intent, revision, checkpoints, target results. Stable caller-supplied Calendar ID/booking UUID or private extended property and lookup on ambiguous insert; verify result before retry. Retry same payment operation without double credit; Telegram callback binds actor/revision and expiry, durable operation ID before advancing update offset. Use Calendar API syncToken pagination and 410 rebuild; commit checkpoint only after durable processing. Full reconcile checks active managed bookings and cancellations regardless of delta horizon; do not interpret missing page or failed read as deletion. Manual sheet row deletion is not cancellation: flag and restore from accepted snapshot; use status Cancelled. Managed calendar deletion => cancellation request, preserve receipts. Native repeated events: import explicit occurrences with stable instance identity or flag for manual resolution; no duplicate expansion of existing series. Generate bounded individual occurrences for new regular rules with unique rule+occurrence key, exceptions/tombstones, no recreating cancelled slots. Never write uncertain availability as free; union live Calendar occupied time and unresolved CRM/pending ranges. Calendar and Sheets have no cross-service transaction; manual overlap races may exist temporarily, detect and surface, do not promise absolute prevention.
 
## Low-maintenance requirements
Validated settings (tariff versions/effective date, hours, discounts, allowed admins, directions) editable without code. Owner-only role changes; never store credentials in visible sheet. One settings source; no duplicate tariff formulas in report layer. Status shows last successful reconciliation, pending/conflicts, trigger counts, backup age, actual known service results, stale/unknown not green. Reuse existing poll/outbox and error alerts. Prefer four existing triggers; process bounded retry queue on existing minute poll only if work due, full reconciliation every 12h; daily backup as due work or separate trigger only if necessary. Validate schema before writes. Rate-limited notices with exact corrective action. No automatic destructive conflict resolution. Backup spreadsheet + restorable event metadata (including original IDs, time zone, recurrence/exception info); daily copy, retain 14 daily and 12 monthly, clean only verified generated backups after successful copy; test isolated restore. Restore/production switch requires owner approval. Goals: <=15 minutes routine maintenance/month measured after pilot, zero routine terminal use, all normal tariff changes without code. No uptime guarantee; quotas, credentials and permissions remain operational risks.
