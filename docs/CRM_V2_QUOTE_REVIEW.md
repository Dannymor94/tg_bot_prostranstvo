# CRM v2 — explicit quote approval (2026-11-25)

- CrmQuoteReview.gs implements actor-bound confirmation of keeping an existing quote or recalculating it for the current accepted booking revision. Existing receipt entries remain untouched; credit/overpayment is flagged, not automatically refunded.
- Telegram booking card offers safe quote options only when the current quote needs review. Once approved, payment actions become available again for a positive outstanding balance. A direct /quote ID | keep or /quote ID | recalculate command is available as fallback.
- Approval requires stable booking across all projections, current revision, unchanged original price snapshot, tariff result and received total. A pending payment marker in Sheet or Calendar must be cleared before price review. Keep is unavailable when changing between internal and billable categories. Recalculation validates opening hours and tenant defaults.
- The accepted quote, revision, version and derived amounts are written together in the existing row. The confirmed command is persisted before writing; retry of a started command after ambiguous flush verifies the already-applied quote. No actual payment or refund is generated by review.
- Quote approval record uses existing Telegram command retention (terminal records eligible for cleanup after seven days; no permanent separate price-decision audit ledger yet). Existing quote metadata and payment history persist. Concurrent human UI edits bypass script lock; strict protection and actual permission checks remain release prerequisites.
