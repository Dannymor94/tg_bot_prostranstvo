# Google Календарь ↔ таблица «Бронирование» + Telegram

Статус: **двусторонний режим установлен в тестовом Google Apps Script**, основная таблица собственника не изменялась. Версия с дополнительной защитой P0/P1 сначала тестируется в отдельной ветке; не считать её установленной до подтверждённого обновления GAS. Ниже сохранено архивное описание старой версии; для развёртывания пользоваться только разделом «Двусторонняя версия».

## Двусторонняя версия — актуальная инструкция

- Оба файла `Code.gs` и `Bidirectional.gs` должны находиться в одном GAS-проекте.
- Ручная правка таблицы обрабатывается `bdOnSheetEdit` для конкретной даты.
- Изменение календаря обрабатывается `bdOnCalendarChange`; `bdTimer` сверяет
  120 дней каждые **15 минут** как резерв (API-записи в Sheet не вызывают onEdit).
- `bdInstallTriggers` сохраняет `pollTelegram`, устанавливает новые обработчики
  и заменяет только устаревший односторонний таймер.
- **Не запускать** старый `installTriggers`. Во время активной двусторонней
  синхронизации он заблокирован.
- `WRITE_ENABLED=true` требуется для любых двусторонних записей.
- Смена тестовых ID на производственные заблокирована до отдельного параметра
  `BIDIR_PRODUCTION_APPROVED=<SPREADSHEET_ID>|<CALENDAR_ID>`. Владелец должен
  предварительно сделать резервную копию и разрешить переход.
- Для безопасной паузы: `bdPause`, для возвращения: `bdResume`.
  Прерванные транзакции осматриваются функцией `bdRecoverPending`.
- Если есть `BD_PENDING_` или синхронизация приостановлена, Telegram не отвечает
  «свободно». Ответ блокируется и на время удержания блокировки записи.
- Перед каждым изменением обе стороны перепроверяются, после изменения
  сверяется точное соответствие часовой проекции. Неудачная проверка оставляет
  дневной журнал `BD_PENDING_` и требует восстановления.
- Перед записью в таблице создаётся скрытый лист `_BD_AUDIT` с временем,
  датой, предыдущими значениями и планом. Это восстановительный след, **не**
  полный бэкап Calendar с гостями и описаниями.
- Автоматически не допускаются массовое удаление более двух событий на одну
  дату, изменение повторяющихся событий из таблицы и одновременная смена имени
  и времени одного события (неоднозначный перенос). Такие случаи требуют
  ручной проверки, чтобы не подменить чужое занятие.
- Старый `syncCalendarToSheet` больше нельзя запускать даже вручную при активном
  двустороннем режиме.
- `BD_STATE_yyyy-mm-dd` хранит последний согласованный набор точных событий
  (ID, имя, время), а не только округленные часовые ячейки.
- Раздельные события с одинаковыми именами сохраняют исходные границы из
  последнего согласованного снимка. Неоднозначные новые правки отклоняются.
- Конфликт на одной дате больше не останавливает синхронизацию остальных дат.
- Telegram: `/free 22 ноября` — свободные окна; `/status` — техническое
  состояние (только OWNER_CHAT_ID). Можно отправить несколько интервалов через
  `;` или с новой строки.
- Telegram хранит ответы в `TG_OUTBOX_*` до подтверждения доставки, повторяет
  временно неудавшиеся попытки до трёх раз и продолжает обрабатывать других
  пользователей. Количество безвозвратно недоставленных ответов видно в `/status`.
- Даты с противоречиями (например, «22 ноября в субботу» для воскресенья)
  отклоняются; «в следующую пятницу» учитывает следующую неделю, явный год
  разбирается с русскими окончаниями названий месяцев.
- Горизонт 120 дней — ограничение резервного поиска. Для Calendars с
  бронированиями на более дальние даты необходим отдельный инкрементальный
  механизм Calendar API, прежде чем обещать синхронизацию любого года.
- Публичный просмотр Google Calendar следует выдавать с правом
  **«Только свободно/занято»**, иначе имена арендаторов будут видны.
- Тестовый Telegram-токен, переданный через чат, рекомендуется отозвать
  перед реальным запуском.

### Контроль качества перед включением в рабочей таблице

1. Выполнить `TZ=Europe/Moscow node --test bidirectional.test.mjs test.mjs`.
2. Проверить в тестовом GAS `bdTimer`: отсутствие конфликтов и незавершённых
   `BD_PENDING_*`, а также наличие листа `_BD_AUDIT` после первой записи.
3. На пустой тестовой дате пройти цикл Sheet → Calendar (сохранить ID),
   затем Calendar → Sheet (`(+30) Мин`), затем удаление и повторная сверка.
4. Отправить Telegram-боту запросы о занятом, свободном и пограничном времени;
   отдельно проверить `/free`, неверные даты и сбой доставки.
5. Проверить четыре триггера: `bdOnSheetEdit`, `bdOnCalendarChange`,
   `bdTimer` (15 минут), `pollTelegram` (1 минута).
6. Перед production: резервная копия исходной таблицы, отдельное разрешение
   на production ID, новый Telegram-токен. Никакие пользовательские данные
   из production не используются в тестах.

Ниже находится **архивное описание односторонней версии**. Оно не является
инструкцией по установке текущего тестового решения.

## Что делает

- Ты добавляешь занятия в **отдельный календарь**; каждые 5 минут они появляются на вкладке `Бронирование` исходной таблицы.
- Перенёс занятие — скрипт очищает старые связанные ячейки и записывает новые.
- Удалил занятие — скрипт удаляет **именно свои**, ранее записанные значения.
- Переименовал или изменил длительность — время и ячейки пересчитываются; в таблице всегда показывается единое `SHEET_LABEL`, а не название занятия.
- Если кто-то изменил ячейку вручную, или её занимает другой преподаватель, скрипт **не затирает** чужое значение; пишет конфликт в журнал и, если настроено, шлёт предупреждение.
- Telegram-бот читает таблицу и календарь при каждом вопросе, отвечает на конкретные интервалы без нейросети и без раскрытия имён.

## Структура подключённой таблицы

- Исходная таблица: «Фин модель Йога студия». Её ID и ID тестовой копии не публикуются в GitHub.
- Тестовая копия: «ТЕСТ — Фин модель Йога студия (GAS)», создана 19.11.2026 в личной папке `ChatGPT` на Google Диске. Ссылка передана владельцу отдельно.
- Лист: `Бронирование`, ID `146122814`
- Даты: колонка **A**, начиная с 6-й строки
- Время: колонки **B:Q**, каждый столбец — час с 06:00 до 22:00
- Часовой пояс таблицы: `Europe/Moscow`

## Установка без терминала

1. В **Google Календаре** создай отдельный календарь, например `Мастерская — занятия Даниила`. Скопируй его идентификатор из настроек календаря → «Интеграция календаря». Использовать личный основной календарь нежелательно.
2. В Telegram через [@BotFather](https://t.me/BotFather) создай **отдельного** бота (`/newbot`). Сохрани токен у себя. Не отправляй токен в чат и не вставляй его прямо в код. Один токен нельзя одновременно использовать с другим уже работающим Telegram-ботом, который получает обновления.
3. Открой [script.google.com](https://script.google.com/) → «Новый проект». Назови `Studio Calendar Sync`.
4. Скопируй содержимое файла **`Code.gs`** в одноимённый файл проекта. В настройках проекта выбери часовой пояс **(GMT+03:00) Europe/Moscow**. При необходимости включи отображение `appsscript.json` и используй приложенный шаблон.
5. В «Настройки проекта → Свойства скрипта» добавь:

   | Свойство | Значение |
   |---|---|
   | `CALENDAR_ID` | ID отдельного календаря |
   | `SPREADSHEET_ID` | **ID тестовой копии** на первых запусках, а не оригинала |
   | `SHEET_LABEL` | Любой текст для обозначения твоих занятий, например `Даниил`; выбирать значение из выпадающего списка не требуется |
   | `TELEGRAM_TOKEN` | Токен нового бота от BotFather |
   | `WRITE_ENABLED` | `false` |
   | `SYNC_DAYS` | `60` (необязательно) |
   | `OWNER_CHAT_ID` | ID Telegram-чата для предупреждений (необязательно) |

6. Убедись, что у этого Google-аккаунта есть права редактировать указанную таблицу и читать события отдельного календаря.
7. Создай в календаре одно **тестовое** занятие в ещё не занятом времени, например на дату в ближайшие 60 дней. В редакторе Apps Script выбери функцию `dryRun` → «Выполнить». Подтверди разрешения Google. В разделе «Выполнения / Журнал» проверь список `changes`, `conflicts` и `warnings` — до этого момента таблица не изменяется.
8. **После проверки dry run** установи `WRITE_ENABLED=true`, один раз запусти `syncCalendarToSheet`. Проверь появившуюся запись в таблице. Перенеси и удали тестовое событие — значения должны обновиться и исчезнуть.
9. Запусти `installTriggers` один раз. Скрипт поставит таймер: календарь → таблица каждые 5 минут, Telegram → ответы раз в минуту.
10. Напиши боту в Telegram, например: `22 ноября с 15:30 до 17:00 свободно?`. Если у бота ранее уже был настроен webhook, его необходимо отключить для этого **отдельного** бота перед использованием `getUpdates`.

## Правило «(+30)» — подтверждено

Для календарного события **15:30–16:30** прототип планирует:

| Колонка | Час | Запись |
|---|---|---|
| K | 15:00–16:00 | `(+30) Даниил` |
| L | 16:00–17:00 | `Даниил` |

При начале в 15:30 скрипт ставит `(+30) Имя` **в колонку 15:00–16:00**, а при начале ровно в 15:00 — просто `Имя`. Там нет отдельного признака «окончание в :30», поэтому второй час визуально выглядит занятым целиком. **Telegram учитывает реальное окончание 16:30 из календаря**, а не округляет твои собственные события. Чужие обычные ячейки считаются занятыми весь час, чужие `(+30)` — с получаса.

События с минутами не `:00`/`:30`, встречи вне диапазона 06:00–22:00 и одновременные события в одной часовой ячейке не записываются без предупреждения. Выпадающий список имён не используется для проверки текста: скрипт записывает значение `SHEET_LABEL` напрямую, не изменяя список. **Если Google Sheets технически запрещает ввод произвольного значения**, появится конфликт; перед включением автоматизации потребуется настроить правило как «показывать предупреждение», сохранив существующие варианты. Скрипт сам не изменяет правила в таблице.

## Что важно про удаление и перезапись

Скрипт хранит по дням собственные записи (`OWN_YYYY-MM-DD`) в закрытых свойствах проекта. При повторном запуске сравнивает фактическую ячейку с последней записью. Если та же — может очистить или заменить. Если другая — останавливает изменение и сообщает о конфликте.

То есть удаление **из Google Календаря действительно приводит к удалению в таблице**, но не к массовой очистке чужих бронирований. Если ты хочешь, чтобы календарь имел право *затирать чужие значения*, это отдельное опасное правило, которое нужно подтвердить явно.

## Примеры Telegram

- `В субботу с 14 до 16 свободно?`
- `22 ноября с 15:30 до 17:00`
- `Завтра с 18 до 19:30`
- `25-го с 15 до 17`

Если указано «вечером» без точного времени, несколько дат одновременно или время без даты, бот просит уточнить. Запросы проверяются на занятость, **не создают бронирование**. Механизм — опрос раз в минуту, поэтому реакция может занимать до минуты и больше при задержках сервисов.

## Логика Telegram-бота (без LLM)

1. **Приём:** триггер `pollTelegram` раз в минуту вызывает Telegram Bot API `getUpdates`. Бот принимает текст обычного или *пересланного* сообщения. `TG_OFFSET` сохраняет последнюю обработанную позицию, чтобы не отвечать повторно. Команды `/start`, `/help` и `помощь` показывают пример запроса.
2. **Разбор:** `parseRussianSlot_` детерминированно извлекает одну дату (`22 ноября`, `22.11`, `сегодня`, `завтра`, `послезавтра`, день недели) и интервал (`15:30–17:00`, `с 15 до 17`). Если дата или границы времени неясны, бот **просит уточнение**, а не угадывает. Интервалы ограничены 06:00–22:00, часовой пояс — Москва.
3. **Проверка:** `checkAvailability_` загружает заполненные ячейки листа `Бронирование` на указанную дату и проверяет пересечение с запросом. Если чужая ячейка содержит `(+30)`, занятость начинается с `:30`. Для собственных записей скрипта используются **точные времена из Google Календаря**, даже если отображение в таблице округлено до целого часа. Ячейки других преподавателей учитываются независимо от календаря.
4. **Ответ:** `✅ По известному расписанию свободно` либо `❌ Занято` с интервалами пересечения, **без имён клиентов и содержания событий**. При технической ошибке бот не сообщает, что свободно — отвечает, что проверить время не удалось.
5. **Безопасность:** бот **ничего не бронирует, не редактирует таблицу и не меняет календарь**. Изменения создаёт только календарная часть скрипта. Токен хранится в `Script Properties` Google, а не в публичном GitHub.

**Ограничение версии MVP:** бот понимает явные дату и диапазон времени, но не произвольные формулировки вроде «в эту пятницу часика на два после обеда», «когда есть два часа подряд?» или сложные сообщения с несколькими альтернативами. Для таких запросов он попросит конкретный интервал. Подключать Groq/LLM пока не требуется; при необходимости можно добавить *только для извлечения даты и времени*, с обязательной проверкой результата детерминированным кодом.

## Эксплуатация

- При `WRITE_ENABLED=false` календарная синхронизация продолжит выдавать отчёт, но не будет менять таблицу; бот продолжит проверять занятость.
- История старых дат после выхода из окна `SYNC_DAYS` не очищается автоматически.
- При ошибке `PENDING_...` **не удаляй свойство наугад**: требуется сверка журнала и фактической ячейки, после чего ручное восстановление права на запись.
- Если BotFather-токен стал известен постороннему, отзови его и обнови свойство проекта.
- Приложение использует бесплатные сервисы в пределах их текущих лимитов. Оно не обладает мгновенным SLA и не заменяет подтверждение аренды ответственным человеком.

## Локальная проверка разработчиком

При установленном Node.js: `TZ=Europe/Moscow node --test test.mjs`.

Тестируются функция отображения интервалов, изменения/удаления, защита чужих значений, повторяемость и разбор русских сообщений. Интеграционный тест с реальным календарём и Telegram выполняется отдельно после установки и выдачи разрешений.
